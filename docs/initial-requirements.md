# Huddle - 專案規格與需求文件

## 1. 專案概述 (Overview)
* **專案名稱**：Huddle
* **產品定位**：基於 Discord Activity 的輕量級活動簽到、破冰互動與協作會議記錄 Web App。
* **目標客群**：Discord 伺服器內的既有成員與社群聚會。
* **核心價值**：零摩擦力登入、一站式簽到與破冰、主動喚醒通知，以及歷史會議記錄回顧。

---

## 2. 核心架構與技術選型 (Architecture & Tech Stack)
* **執行環境**：Discord Embedded App SDK (Activity / Iframe)。
* **身分驗證**：直接取用 Discord SDK 授權取得 User ID 與基本資料，免除傳統帳號密碼註冊。
* **通知與喚醒**：搭配 Discord Bot 進行頻道訊息推播與活動開始時的 Modal 喚醒。
* **資料儲存**：後端統一管理活動、簽到狀態、破冰回答與下次時間意願（異動直接以最新資料覆蓋）。

---

## 3. 使用者故事總表 (User Stories)

| 模組 | 功能編號 | As (角色) | Want (期望) | So That (目的) | 核心程度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **身分與入口** | US-01 | Discord 社群成員 | 打開 Activity 時直接取得 Discord 身分登入 | 不用另外註冊與登入，實現零摩擦力體驗 | **P0 (核心)** |
| **個人狀態頁** | US-02 | 參與者 | 打開 Activity 第一眼看到「我的個人狀態頁」（個人參與記錄、歷史破冰回答、下次時間提案） | 從個人視角出發，快速掌握自己與社群的互動概況 | **P0 (核心)** |
| **活動互動** | US-03 | 參與者 | 在同一個介面上點選出席狀態 (Yes/No/Maybe)、回答破冰問題、並填寫下次時間意願 | 一站式完成簽到與互動，降低填寫的繁瑣感 | **P0 (核心)** |
| **活動主動喚醒** | US-04 | 參與者 | 當有訂閱或參加的活動即將開始/已開始時，Activity 中自動跳出 Modal 提醒前往 | 透過主動推播減少遺忘，提升活動當下的出席與簽到率 | **P1 (重要)** |
| **活動建立與管理** | US-05 | 主辦人 | 建立新活動（填寫名稱、說明、預定時間，以及選填的破冰問題） | 開啟新場次並引導成員互動 | **P0 (核心)** |
| **排程與決議** | US-06 | 主辦人 | 檢視大家的下次時間意願統計，並在系統上「決議並鎖定」下次正式時間 | 統整共識並讓成員明確知道下一次聚會時間 | **P0 (核心)** |
| **歷史回顧** | US-07 | 參與者 / 主辦人 | 透過次要路徑進入「活動列表」，瀏覽過去所有活動、出席狀況與歷史會議記錄 | 隨時翻閱過往脈絡，發揮線上協作會議記錄的價值 | **P0 (核心)** |
| **通知與訂閱** | US-08 | 參與者 | 透過 Discord Bot 頻道訊息掌握活動動態與新記錄 | 在習慣的頻道中即時收到通知，不漏接重要資訊 | **P1 (重要)** |

## 4. 關鍵設計決策與規則 (Design Decisions & Rules)

1. **簽到狀態覆蓋**：
   * 參與者修改出席狀態或意願時，系統直接以最新送出的資料覆蓋舊記錄，不需維護詳細的修改歷程 (Audit Log)。
2. **下次時間意願機制**：
   * 主辦人在建立活動時可指定意願填寫類型：
     * **(a) 絕對時間**（具體日期與時段選項勾選）
     * **(b) 相對時間**（例如：「兩週後」等概念）
     * **(c) 自由填寫**（參與者自定文字）
   * 系統後端統一以字串（String / JSON）儲存，不作過度自動化的時間解析或投票決議運算，完全交由主辦人手動檢視與手動鎖定。
3. **歷史與匯出**：
   * 第一階段暫不考慮匯出或外部權限控制，全面聚焦於 Discord 社群內部的協作與回顧體驗。
