# ADR 0006：Event 生命週期手動推進、每個 Series 最多一場待辦、破冰盲揭

- 狀態：已接受
- 日期：2026-10-03

## 背景

需要決定 Event 何時算「進行中」與「結束」、下一場如何產生、取消如何處理，以及破冰回答的可見性。

## 決策

**生命週期**
- `scheduled → live → ended`，或 `scheduled → cancelled`，**全部由人手動推進**（主持人或主辦）。時間不會自動改變狀態，忘記開始或結束的風險已接受。
- 只存預定的 `starts_at` 與實際的 `started_at`、`ended_at`，沒有預定結束時間。
- 首頁 CTA 以時間窗限制顯示範圍：`live` 或已進入提前顯示時間，且在實際（或預定）開始後 12 小時內。

**下一場**
- 每個 Series **最多一場 `scheduled`**（DB 以 partial unique index 保證）。
- 鎖定第 N 場的意願時建立第 N+1 場；取消待辦 Event 後，由主辦**手動**建立下一場。MVP 不做改期。
- 編號在建立時取號，**取消也佔號**。

**破冰盲揭**
- 每場最多一題。未揭曉的內容**只有作者看得到**，主持人也看不到，只能從「已作答的人」中挑選。
- 隨機揭曉由 server 選人，所有人同步看到轉盤動畫，動畫結束才送出內容。
- 揭曉後鎖定不能修改；Event 結束時全部公開。

## 影響

- 狀態轉換規則單純，容易測試。
- 不需要排程工作來自動結束活動。
- 盲揭過濾必須在 query 層實作並有測試保護。
